# 汉字盲盒（第一次复刻）后端设计文档

> 本文档依据现有前端（`static/index.html` + `static/app.js`）的接口调用契约编写，
> 后端开发严格按本文档实现，接口路径、请求/响应格式与前端保持一致。

---

## 1. 项目概述

汉字谜盒是一款基于 AI 的字谜互动游戏。前端负责界面渲染与发起请求，**会话的新建 / 列表 / 删除 / 消息发送全部由后端处理**，前端不本地创建任何会话数据。

后端需提供 5 个 RESTful 接口，覆盖：

| 功能 | 方法 | 路径 |
| --- | --- | --- |
| 新建会话 | POST | `/api/sessions` |
| 会话列表 | GET | `/api/sessions` |
| 删除会话 | DELETE | `/api/sessions/{session_id}` |
| 会话历史 | GET | `/api/sessions/{session_id}` |
| 发送消息 | POST | `/api/chat` |

## 4. 全局约定

### 4.1 统一响应格式（硬性要求）

所有接口统一返回 `{code, message, date}` 结构，`date` 字段存放真正的业务数据：

```json
{
  "code": 200,
  "message": "操作成功提示语",
  "date": "业务数据"
}
```

> 前端 `app.js` 的 `request()` 会自动解包 `date` 字段，调用方拿到的就是 `date` 里的数据。
> 前端还兼容 `data` 字段的旧格式，但**新后端必须使用 `date`**。

### 4.2 HTTP 状态码

前端 `request()` 依据 `res.ok`（2xx）判断请求是否成功，因此：

- 成功：一律返回 `200`，body 为 `{code:200, ...}`
- 业务失败（如会话不存在）：返回 `404`，body 为 `{code:404, message, date:null}`
- 服务器内部错误：返回 `500`，body 为 `{code:500, message, date:null}`
- 删除接口如按 RESTful 规范返回 `204`，前端也已兼容（`request()` 对 204 直接返回 null），但不强制

### 4.3 RESTful 规范

- 资源用复数：`/api/sessions`
- 操作语义由 HTTP 方法表达：POST 新建、GET 查询、DELETE 删除
- 所有接口路径统一加 `/api` 前缀
- 静态资源挂载到 `/static`，前端引用必须使用 `/static/` 开头的根路径（`index.html` 已如此）

### 4.4 静态资源与首页

- `app.mount("/static", StaticFiles(directory="static"), name="static")`
- 根路由 `GET /` 返回 `static/index.html`（使用 `FileResponse`）

## 5. 数据存储设计

### 5.1 会话 ID 生成规则

```python
def create_session_id():
    return datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
```

- 形如 `2026-10-20_14-30-00`
- **禁止使用冒号**（`HH:MM:SS` 格式会触发 Windows 文件名非法错误）
- 该 ID 同时也是前端显示的"会话名称"和文件名主体，三者保持一致

### 5.2 会话文件结构

每个会话一个 JSON 文件，存放在 `sessions/` 目录，命名为 `{session_id}.json`：

```json
{
  "session_id": "2026-10-20_14-30-00",
  "messages": [
    { "role": "user", "content": "一个太阳（打一字）" },
    { "role": "assistant", "content": "答对了！是"日"字！要不要再来一题？" }
  ]
}
```

**硬性要求：用户消息和 AI 回复必须同时持久化，只存一方会导致历史记录缺失。**

### 5.3 会话列表排序

- 会话 ID 是时间戳字符串，直接按字符串倒序排列（`sort(reverse=True)`）即等于按创建时间倒序，最新会话在最前
- 前端约定：列表第一条就是当前最新会话，页面加载后自动选中第一条

### 5.4 会话文件读写

`function.py` 统一封装：

```python
def get_json_name(session_id):      # 返回 f"{session_id}"
def load_session_data(session_id):  # 读取并解析 JSON，返回 dict
def save_session_data(session_id, session_data):  # 写入 JSON
```

注意事项：
- 读写路径必须全局统一使用 `sessions/` 前缀 + `get_json_name` 的命名规则，避免路径不匹配导致 `FileNotFoundError`
- `json.dump()` **必须传入文件对象参数**，否则抛 TypeError 导致接口 500
- 写入时用 `ensure_ascii=False, indent=4`，读取时用 `encoding="utf-8"`

## 6. 接口详细设计

以下 5 个接口，请求/响应示例均为完整 JSON。

### 6.1 新建会话

| 项 | 内容 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/api/sessions` |
| 请求体 | 无 |
| 前端调用 | `newGame()`，创建成功后前端重新拉取列表 |

**成功响应（200）：**

```json
{
  "code": 200,
  "message": "会话创建成功",
  "date": "2026-10-20_14-30-00"
}
```

**实现要点：**
1. 生成会话 ID
2. 构造 `{session_id, messages: []}` 写入 `sessions/{session_id}.json`
3. `date` 返回会话 ID 字符串（前端拿到的是字符串）

### 6.2 获取会话列表

| 项 | 内容 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/sessions` |
| 请求体 | 无 |
| 前端调用 | `loadSessions()`，`sessions[0]` 为当前会话 |

**成功响应（200）：**

```json
{
  "code": 200,
  "message": "会话列表加载成功",
  "date": ["2026-10-20_14-30-00", "2026-10-20_13-00-00"]
}
```

**实现要点：**
1. 列出 `sessions/` 目录下所有 `.json` 文件，去掉扩展名得到会话 ID
2. 按字符串倒序排序（最新在前）
3. `date` 返回**会话 ID 字符串数组**

### 6.3 删除会话

| 项 | 内容 |
| --- | --- |
| 方法 | `DELETE` |
| 路径 | `/api/sessions/{session_id}` |
| 请求体 | 无 |
| 前端调用 | `deleteSession(id)`，删除成功后前端重新拉取列表 |

**成功响应（200）：**

```json
{
  "code": 200,
  "message": "会话删除成功",
  "date": null
}
```

**实现要点：**
- 文件存在则 `os.remove` 删除，不存在则返回 404（前端已有错误提示逻辑）
- 删除动作由后端完成，前端只发请求

### 6.4 获取会话历史

| 项 | 内容 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/sessions/{session_id}` |
| 请求体 | 无 |
| 前端调用 | `selectSession(id)`，`renderMessages(data.messages)` |

**成功响应（200）：**

```json
{
  "code": 200,
  "message": "会话消息加载成功",
  "date": {
    "current_session": "2026-10-20_14-30-00",
    "messages": [
      { "role": "user", "content": "一个太阳（打一字）" },
      { "role": "assistant", "content": "是"日"字！要不要再来一题？" }
    ]
  }
}
```

**实现要点：**
- 前端注释明确要求 `date` 为 `{current_session, messages}` 结构
- `messages` 数组元素格式为 `{role, content}`，`role` 取 `user` 或 `assistant`，前端据此渲染 👤 / 🤖 气泡
- 会话不存在返回 404

### 6.5 发送消息（核心接口）

| 项 | 内容 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/api/chat` |
| 请求体 | `{ "session_id": "2026-10-20_14-30-00", "message": "我的答案是日" }` |
| 前端调用 | `sendMessage()`，前端按 `date` 的类型取值：字符串直接显示；对象则取 `reply` 或 `message` 字段 |

**成功响应（200）：**

```json
{
  "code": 200,
  "message": "聊天成功",
  "date": "太棒了！答对了！就是'日'字！要不要再来一题？"
}
```

> 推荐 `date` 直接返回 AI 回复字符串（最简、前端直接显示）。
> 若返回对象，则必须含 `reply` 字段，如 `{"reply": "..."}`。

**实现要点（结合 7 节业务流程）：**
1. 校验会话存在，不存在返回 404
2. 加载会话历史，调用 AI 模块获取回复
3. **同时保存用户消息和 AI 回复**
4. `date` 返回 AI 回复内容

## 7. 发送消息核心业务流程

```
用户输入 → 前端 appendMessage(user) → POST /api/chat {session_id, message}
  → main.py 校验会话存在（不存在→404）
  → AI_interaction.get_ai_response(session_id, message)
      1. load_session_data(session_id)          # 加载历史
      2. 构建模型消息 = [system 提示词] + 历史 messages + [当前用户消息]
      3. 调用 DeepSeek，获得 AI 回复
      4. session_data["messages"].append({role:"user", content:message})        # ★存用户消息
      5. session_data["messages"].append({role:"assistant", content:回复})      # ★存 AI 回复
      6. save_session_data(session_id, session_data)                           # 保存
      7. 返回 AI 回复字符串
  → main.py 封装 {code:200, message, date:回复字符串} 返回前端
  → 前端 removeTyping() + appendMessage(reply, "ai")
```

**构建给模型的 messages 时，系统提示词放在列表首位**，历史消息依次追加，最后追加本次用户消息。

## 8. AI 交互模块设计（`AI_interaction.py`）

### 8.1 客户端初始化

```python
client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY_1"),
    base_url="https://api.deepseek.com"
)
```

### 8.2 系统提示词（SYSTEM_PROMPT）核心要求

1. **出题规则**：每次出一个字谜，格式固定为 `"谜面"（打一字）`；避开已出过的谜语，保证随机不重复；谜语常见、难度适中
2. **判题规则**：识别模糊表述（如"江字""江""jiang"都解析为「江」）；答对用欢快语气反馈；**答错只给线索，严禁泄露答案**
3. **互动流程**：开场主动出题；答对后询问是否继续，继续则出新题，不继续则告别
4. **语气**：轻松有趣、简洁明快，不聊与字谜无关的内容，不滥用表情符号

### 8.3 模型调用参数（参考）

```python
response = client.chat.completions.create(
    model="deepseek-flash",
    messages=messages,
    stream=False,
    temperature=1.5,        # 输出随机性/多样性
    reasoning_effort="high",
    extra_body={"thinking": {"type": "enabled"}}
)
new_message = response.choices[0].message.content
```

## 10. 错误处理与全局异常

```python
@app.exception_handler(Exception)
def handle_exception(request, exc):
    logging.error(f"异常的请求{request.url} 异常信息：{exc}")
    return JSONResponse(
        status_code=500,
        content=ApiResponse(code=500, message="服务器内部错误", date=None).model_dump()
    )
```

要点：
- 全局兜底：捕获所有未处理异常，记录日志，返回 `{code:500, message, date:null}`，**HTTP 状态码为 500**（前端 `res.ok` 检查会触发错误提示）
- 业务错误（会话不存在）用 `JSONResponse(status_code=404, ...)` 或直接抛 `HTTPException(404)`
- 可预期错误（404 等）和兜底异常（500）分开处理

## 12. 开发注意事项（易踩坑清单）

1. **保存会话必须同时存用户消息和 AI 回复**，只存一方 → 历史记录缺失
2. `json.dump()` 必须传文件对象参数（`json.dump(data, f)`），否则 TypeError → 接口 500
3. 会话文件名时间戳**禁止冒号**（Windows 非法文件名）
4. 读写会话路径必须全局统一（`sessions/` 前缀 + `get_json_name`），否则 `FileNotFoundError`
5. 循环变量命名**不能与函数入参重名**（否则覆盖入参，导致 AI 消息内容类型错误 → 接口 500）
6. 判断列表是否有内容用 `if 列表` 而非 `if 列表 is not None`
7. 函数 `return` 必须保证所有路径都能走到，避免返回 None 引发迭代错误
8. 后端接口路径必须带 `/api` 前缀，响应统一 `{code, message, date}`
9. 删除会话前用 `os.path.exists()` 判断，不存在时返回 404
10. 前端页面每次加载都会自动新建一个会话（`DOMContentLoaded` 内先 `loadSessions()` 再 `newGame()`），属正常行为
